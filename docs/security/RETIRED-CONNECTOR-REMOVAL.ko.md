# Dependency-Track 제거 및 기존 Linux 설치 전환

2026-10-19 기준. KODA와 KODA SBOM Tracker는 별도 프로젝트로 유지합니다.

## 적용 내용

- 제품의 연결 API·설정·업로드·재시도·마이그레이션 화면·전용 실행 도구와 배포 서비스 구성을 제거했습니다.
- Grype, 자체 분석·정책·SSVC·CPE·EPSS·오프라인 데이터 반입·SPDX·VEX 기능은 유지합니다.
- Linux 설치기는 서명된 새 배포물을 검증한 후 기존 환경의 Compose 프로젝트·서비스·볼륨 소유권을 확인하고 이전 전용 컨테이너와 볼륨을 제거합니다.
- 이미지가 다른 컨테이너에서 사용 중이면 보존합니다. 관련 없는 이미지 별칭은 삭제하지 않습니다.
- 공유 PostgreSQL 안에서는 이전 전용 DB와 역할의 이름·소유권을 확인한 후 해당 DB·역할만 정리합니다. 자체 Tracker DB·SBOM 원본·분석 이력·아티팩트 볼륨은 유지합니다.
- 앱 시작 시 이전 연결용 테이블·설정 컬럼·대기 작업을 정리합니다. 기존 반입 SBOM이 참조하는 legacy-imports 원본은 보존합니다.
- 기존 설치 폴더의 전용 도구·소스·이미지 tar·환경변수도 정리합니다. 다른 서비스가 공유하거나 소유권이 불명확한 자원은 자동 삭제를 중단하고 오류로 보고합니다.

## 운영상 주의

설치 중 기존 API·작업자를 잠시 정지하고 새 버전으로 시작합니다. 설치 전 조직의 정상 백업 절차를 수행하십시오. 새 백업·복원 경로는 자체 Tracker 데이터만 취급하며 이전 전용 서비스 데이터를 복원하지 않습니다.

정리 스크립트의 제거 대상 식별자와 회귀 테스트에는 이전 제품명이 남습니다. 이는 삭제용 식별 정보이며 재설치나 연결 기능이 아닙니다. 오래된 전체 서비스 구성을 부분 패치로 유지하지 않도록 신규 설치 전환을 요구합니다.

GitHub 비게시 로컬 설정·runtime·빌드·과거 배포 자료는 이번 작업에서 삭제하지 않았습니다. 개인정보·회사 식별정보 점검은 별도 마스킹 보고서에 기록했습니다.

## 검증 경계

컨테이너·볼륨·이미지 소유권과 공유 자원 보호, DB 식별자·소유권, 파일·환경변수 정리, 설치 순서는 회귀 테스트로 검증했습니다. 현재 Mac의 실제 운영 Docker 자원은 삭제하지 않았으며, 대상 Linux에서의 실제 업그레이드 실행은 별도 환경 검증이 필요합니다.

# 스케줄 점검 구현 검증 — 2026-09-07

판정: 주요 흐름은 구현되었으나 승인 계획 전체의 완료 및 운영 배포 준비 완료로 판정하지 않는다.

## 이번 검증에서 수정한 결함

- 임시 수집 파일과 압축 해제본을 모두 삭제한 뒤에만 Tracker/GitLab 전달을 시작한다. 삭제 실패는 정상 완료로 처리하지 않는다.
- 분석은 별도 프로세스 그룹으로 실행하고 제한시간/취소 시 종료한다.
- Portal 재시작 복구가 별도 스케줄 worker의 작업을 가져가지 않도록 분리한다.
- SCP 전송 속도 제한, 디스크 여유 검사, 영속 큐의 순차 실행과 전송 재시도를 보완한다.
- Tracker 업로드 후 조회가 실패하면 같은 Tracker 실행을 조회하고, 저장된 결과로 동일 GitLab 결과를 갱신한다.
- GitLab 이슈 식별자를 개별 취약점 기준으로 안정화하고 닫힌 MR도 재사용한다.
- Tracker 전체/변경분 환경을 분리하고 장기 실행 worker에서 90일 정리를 주기적으로 수행한다.
- 설정 화면의 JavaScript 구문 오류와 분석 전 수집 실패가 결과에서 누락되는 문제를 수정한다.

## 증거 범위

- KODA 스케줄 집중 테스트 21개 통과. 성공/실패/취소/삭제 실패, 실제 분석 프로세스, 제한시간 종료, 변경분/규칙 변경, 수동 작업 우선, 파일 수 제한, SSH 옵션, 재시도, 원본 없는 재전송, 게시 중복 방지, 설정 JavaScript를 검증했다.
- Linux amd64 기존 이미지에 현재 코드를 읽기 전용 마운트하여 18개 테스트 통과. 네트워크 차단, CPU 1개, 메모리 4GiB로 실행했다. 512MiB 테스트용 tmpfs에서 여유공간 예약값만 0으로 조정했다. 신규 배포 이미지 빌드 검증은 아니다.
- Tracker 백엔드 80개 통과. Web typecheck, lint, production build 통과.
- KODA 전체 테스트의 첫 실행은 435개 중 433개 통과/1개 실패/1개 건너뜀. 실패는 Git 제외된 samples/report-designs HTML이 worktree에 없는 원인이었으며 원본에서는 통과했다. 동일 샘플을 복사한 최종 전체 재검증은 436개 중 435개 통과/1개 건너뜀으로 실패 없이 완료했다.
- GitLab/Tracker 전송과 원격 SSH 수집은 테스트 대역을 사용했다. 실제 서버 연결, 실제 MR/Issue 게시 및 장애 복구를 증명하지 않는다.

## 남은 구현/검증 항목

1. worker는 현재 Portal DB를 직접 공유한다. 계획의 제한된 내부 API 및 worker 전용 인증/최소 권한 경계는 아직 구현되지 않았다.
2. CPU/메모리/전송속도/대기시간은 환경설정으로 조정한다. 관리자 화면에서 조정하는 계획까지는 구현되지 않았다.
3. worker 자체 SIGKILL 상황에서 자식 분석 프로세스의 잔존 여부, 대량 원격 파일 목록 및 전송 중 파일 증가에 대한 상한, 실행 중 삭제 실패의 주기적 재정리에는 추가 검증/보완이 필요하다. 재시작 정리 테스트와 동일한 보장으로 취급하지 않는다.
4. 실제 SSH 단절/호스트키 거부/권한 오류, 실제 GitLab 재전송 중복 방지, 신규 이미지 패키징 및 브라우저 시각 검증, 1개 대상 시범 운영의 응답시간/CPU/메모리 측정은 미실행이다.

원본 security 작업, 운영 컨테이너 및 운영 데이터는 변경하지 않았다. KODA 변경은 security-batch worktree에, Tracker 변경은 기존 Tracker 저장소에 남겨 검토할 수 있다. 운영 배포/게시를 수행하지 않았다.

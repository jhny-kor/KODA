# macOS 로컬 AI 개발 가이드

> 기준일: **2026-10-11**. 이 문서는 로컬 작업 트리의 개발 구현을 소스로 확인한
> 가이드입니다. 현재 AI 소스·개발 스크립트·테스트는 미게시 작업 파일이므로, 문서
> 게시만으로 GitHub 체크아웃에서 아래 명령이 실행되거나 Mac App Store 앱에
> 기능이 제공된다는 뜻은 아닙니다. App Store 배포·공증·릴리스 포함 여부는 별도입니다.

macOS 네이티브 앱은 OpenAI 호환 로컬 서버의 `/models`와
`/chat/completions`를 사용합니다. AI 연결에는 별도 SDK가 필요 없습니다.
Python 수정본의 구문 검사에는 이 Mac에서 실행 가능한 Python 3이 필요합니다.
공유 Python 엔진의 `--ai-triage`와 별도 구현입니다.

## 개발 앱 실행

아래 명령은 `script/build_and_run.sh`와 로컬 AI 개발 파일이 있는 체크아웃에서만
사용합니다. `--verify`는 빌드 후 앱 실행과 프로세스 존재를 확인하며, 기능 테스트
전체를 실행하지 않습니다.

```bash
./script/build_and_run.sh --verify
```

앱은 `.build/macos-local-ai/Build/Products/Debug/KODA.app`에 생성됩니다.
번들 ID `com.jhnykor.koda.localai`로 설치된 배포 앱과 설정·키체인을 분리합니다.
스크립트는 ad-hoc 서명(`CODE_SIGN_IDENTITY=-`)을 사용하고 Java 스캐너 번들을
제외합니다(`KODA_INCLUDE_JAVA_SCANNER=0`). 이는 App Store 배포 서명이 아닙니다.

## 연결

1. 이 Mac에서 OpenAI 호환 채팅 모델 서버를 실행합니다.
2. **설정 → 로컬 AI**에서 주소를 입력합니다. 예: `http://127.0.0.1:1234/v1`.
3. 필요한 경우에만 API 키를 입력하고 **모델 목록 조회 → 서버 모델 선택**에서 채팅 모델을 고릅니다. 임베딩 전용 모델은 채팅 응답에 적합하지 않습니다.
4. 이름을 입력하고 **연결 저장**을 누릅니다. 이름·주소·모델은 이 Mac의 UserDefaults에, 키는 서버 주소별 macOS 키체인에 저장합니다. 빈 키로 저장하면 해당 서버의 키체인 키를 삭제합니다.
5. **응답 테스트**로 실제 채팅 응답을 확인합니다. 같은 서버의 다른 모델은 **새 연결**로 추가합니다.
6. 설정과 검사 항목의 **저장된 연결 선택**에서 연결을 바꿉니다. 선택은 다음 실행에도 유지됩니다.

기존 단일 주소·모델은 처음 열 때 저장된 연결로 이전합니다. 연결 삭제는 서버의
키체인 키를 삭제하지 않습니다. 모델 목록 조회 성공은 추론 성공을 뜻하지 않습니다.
요청은 사용자가 버튼을 눌렀을 때 발생하며, 대기 중 취소하거나 화면을 닫아 취소할 수 있습니다.

## 전송 범위와 결과의 의미

모든 네이티브 AI 요청은 `localhost`, `127.0.0.1`, `::1`의 HTTP(S) 주소만
허용합니다. LAN/클라우드 주소는 지원하지 않습니다. 리디렉션을 차단하고 세션의
프록시·쿠키·캐시를 사용하지 않습니다. 로컬 서버 자체의 외부 연결 여부는 별도로
확인해야 합니다. 저장된 연결 목록에는 API 키가 포함되지 않습니다.

| 기능 | 모델에 전달하는 내용 | 결과의 한계 |
|---|---|---|
| AI 설명 | 룰 ID, 제목, 원래 심각도, 권장 조치 | 파일 내용·경로를 보내지 않는 참고 설명 |
| 오탐·위험 검토 | 현재 파일을 다시 점검한 뒤 발견 줄 주변 최대 11줄(최대 4 KiB), 파일명·줄번호와 점검 메타데이터 | 위험 가능성·오탐 가능성·판단 보류 의견; 기존 발견·심각도 유지 |
| 수정본 만들기 | 선택 파일 전체, 파일명·줄번호, 룰 ID, 제목, 권장 조치 | 원본 불변; 검증된 후보만 비교·별도 저장 |
| 회귀 테스트 초안 | 수정 전후 소스, 룰과 권장 조치 | 자연어 테스트 계획이며 **미실행**; 실행 코드·통과 증명 아님 |
| 변경 영향 분석 | 최대 30개 선언 이름과 검색 개수 | Python 텍스트 호출 후보; 경로·소스는 모델에 보내지 않으며 완전한 호출 그래프 아님 |
| AI 보조 보고서 | 앞의 최대 12건의 규칙 ID·분류·심각도·확인 상태 | 발견 수·심각도·위험점수는 원본 고정; 별도 Markdown, 미검증 제안 |

오탐 검토는 최대 512 KiB 파일에서 문맥을 읽습니다. 오탐 검토·수정본 생성은 비밀정보가 감지된 파일, 현재 파일과 맞지 않는 점검 결과,
불완전한 재점검을 거부합니다. 비밀 탐지의 완전성을 보장하는 것은 아닙니다.
AI 보조 보고서는 소스·경로·증거·경고를 전송하지 않으며, 12건을 넘는 항목은 원본
보고서를 참조하도록 안내합니다. AI 설명·검토·보조 보고서는 원본 판정을 바꾸지 않습니다.

## 수정본 검증과 별도 저장

**전체 조회 → 조치 가이드 → 로컬 AI 설명 → 수정본 만들기**에서 `.py`, `.java`,
`.xml`, `.js` 파일을 대상으로 합니다. 입력은 최대 12 KiB, 후보는 최대 24 KiB입니다.
호스트·비밀정보·의존성 발견 항목은 소스 수정 대상에서 제외합니다.

KODA는 요청한 발견이 현재 소스에도 있는지 확인하고, 다른 내용인 후보에 대해
언어별 구문·기본 인터페이스 검사를 수행합니다. 별도 임시 파일을 재점검해 해당
발견이 사라지고 새 발견이 생기지 않았는지 확인하며, 생성 중 원본이 바뀌면 중단합니다.

| 언어 | 검증 도구와 경계 |
|---|---|
| Python | 실행 가능한 Homebrew/Xcode/Command Line Tools Python 3; AST 구문과 기존 함수·클래스 인터페이스 확인 |
| Java | JDK 11 이상 구문 파서와 주요 선언 확인; 의존성 컴파일·프로젝트 빌드·실행은 하지 않음 |
| XML | 외부 엔티티를 비활성화한 파서; 루트·네임스페이스·요소 수·이름/ID 속성 확인 |
| JavaScript | JavaScriptCore 구문 검사·주요 선언 확인; ES 모듈 등은 접근 가능한 Node.js의 `--check`로 대체 |

필요한 도구를 찾거나 실행할 수 없으면 검증 불가로 중단합니다. 설치된 도구도
App Sandbox에서 접근하지 못할 수 있습니다. 일반 `/usr/bin/python3` 대신 직접
실행 가능한 Python 경로를 찾습니다. 생성 코드를 실행하지 않습니다.

**자동 수정·재점검 (최대 3회)**는 구문·인터페이스·재점검 실패를 같은 로컬 모델에
전달해 다시 생성합니다. 직전 후보는 최대 4 KiB일 때만 재전송합니다. 같은 후보
반복, 3회 실패, 원본 변경, 비밀정보, 불완전한 스캔, 연결·출력 한도 오류는 중단합니다.
후보가 검증을 통과하면 **수정본을 별도 파일로 저장**할 수 있고 원본 덮어쓰기는
거부합니다. 회귀 테스트 초안은 모든 지원 언어에서, 변경 영향 분석은 Python에서
사용할 수 있습니다. 검색은 최대 400개 Python 파일·5,000개 엔트리·총 4 MiB·80개
호출 후보로 제한되고 생략 범위를 경고로 표시합니다.

**구문·인터페이스·KODA 재점검 통과는 기능 동등성을 증명하지 않습니다.** 별도
저장한 후보를 프로젝트의 기능·보안 테스트로 검증한 뒤 적용 여부를 판단하세요.

## 응답 제한과 문제 해결

채팅 요청은 SSE 스트리밍으로 최종 답변만 모으고 추론 조각은 결과에 보관하지
않습니다. `[DONE]`과 정상 종료 이유 `stop`을 요구하며, 토큰 한도 종료·빈 답변·
불완전한 연결 종료를 거부합니다. 전체 스트림은 16 MiB, 한 이벤트 줄은 128 KiB,
최종 답변은 64 KiB를 상한으로 둡니다. 모델 목록 등 비스트리밍 응답은 1 MiB로 제한합니다.

일반 수정본·오탐 검토·회귀 계획·AI 보고서 요청은 응답 데이터 대기 최대 10분,
전체 최대 25분입니다. 응답 테스트·영향 분석은 최대 10분, 자동 수정 반복은
요청당 최대 5분·최대 3회입니다. 반복 전체에 별도 15분 타이머가 있는 것은 아니며
로컬 검증 시간도 필요합니다. 언제든 취소할 수 있습니다.

시간 초과·추론만 있는 답변이면 서버의 진행 중인 생성을 확인하고 작은 파일이나
더 빠른 채팅 모델로 다시 시도하세요. 서버가 지원하는 추론 강도 설정을 낮출 수도
있지만 수정 품질이나 기능 보존을 보장하지는 않습니다.

## 검증 명령과 이전 기록

아래 테스트도 미게시 개발 파일이 있는 체크아웃에서만 실행할 수 있습니다.
**2026-10-11에는 아래 로컬 AI fixture 7종을 포함한 macOS 검증 스크립트
10종을 모두 통과했습니다.** Java 자산을 포함한 arm64·x86_64 Release 전체
빌드·정적 분석, ARM에서 실제 앱 창과 headless Java 검사를 확인했습니다.
이는 로컬 AI 화면의 전체 상호작용이나 실제 모델의 새 추론 결과를 검증한 것은
아닙니다. Intel 실행·스토어 배포·공증도 미검증입니다.
[현재 검증 기록](verification-2026-10-11.ko.md)을 참고하세요.

```bash
python3 platforms/macos/tests/test_local_ai_client.py
python3 platforms/macos/tests/test_local_ai_profiles.py
python3 platforms/macos/tests/test_native_local_ai_fix.py
python3 platforms/macos/tests/test_native_local_ai_triage_review.py
python3 platforms/macos/tests/test_native_local_ai_test_plan.py
python3 platforms/macos/tests/test_native_local_ai_impact.py
python3 platforms/macos/tests/test_native_ai_report.py
```

위 7종에 네이티브 아카이브·Java 프로세스·Java 자산 패키징 검증 3종을 추가한
10종이 현재 검증 범위입니다. 정상 빈 ZIP/GZIP과 손상된 압축 데이터, 양쪽
프로세스 출력의 동시 읽기·시간 초과, 잘못된 helper 아키텍처 거부를 확인했습니다.
fixture 응답은 실제 모델의 분석 정확도를 입증하지 않습니다.

2026-10-02 기록의 `python3 -m unittest discover -s platforms/macos/tests -q`
결과(로컬 AI 7종과 당시 아카이브 5개)는 이전 구현의 회귀 기록입니다.

기존 2026-09-28~29 개발 기록은 다음과 같습니다. 현재 환경의 통과 증거로 사용하지 않습니다.

- 9월 28일 LM Studio 모델 조회·응답·AI 설명과 스트리밍 오탐 검토를 기록했습니다. 고정 응답 서버로 후보 비교·별도 저장·회귀 계획·호출 후보·AI 보고서 화면도 기록했습니다.
- 같은 날 `qwen3.8-27b-mlx`의 작은 Python 수정본이 약 5분 후 표시됐지만 허용 명령 범위를 바꾼 제안의 기능 보존은 확인하지 않았습니다.
- 9월 29일 fixture로 2회차 성공·동일 후보 중단·3회 제한 등을, `koda-qwen3.8-no-think`의 작은 Python 예제로 1회차 후보 통과를 기록했습니다. 실제 모델의 2회차 재시도는 별도 검증이 필요합니다.
- Java·XML·JavaScript 확장 후 XML/일반 JS 후보 표시를 기록했으나, 당시 JDK가 없어 Java 성공 경로를, 샌드박스의 Node.js 접근 제한으로 ES 모듈 성공 경로를 확인하지 못했습니다. 이 도구들의 현재 설치 상태는 재확인해야 합니다.

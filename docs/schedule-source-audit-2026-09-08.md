## 재현 증거

`PYTHONPATH=platforms/shared/python KODA_SCHEDULE_NO_SLEEP=1 python3 -m tests.schedule_remaining_probe`

종료 코드 **1**: 아래 요구 보장 4개가 충족되지 않았다는 감사 결과다. 정상 회귀 테스트 통과로 세지 않는다.

1. `max_files=1`에서 collector가 2개 목록을 반환했다. 상위 호출자는 나중에 거부하므로 점검 자체가 제한 없이 진행된다는 의미는 아니다.
2. `max_bytes=8`에서 작은 테스트 대역이 64바이트를 쓴 뒤에야 거부됐다. 실제 SCP 초과 전송 실험은 아니며, fetch와 사후 검사 사이의 경계를 재현한다.
3. 삭제 실패를 일으킨 후 다음 `run_once()`를 실행해도 `cleanup_status=failed`였다.
4. 실제 `_analyze()` 감독 코드를 실행하되 분석 작업만 sleep 프로세스로 대체했다. 부모 SIGKILL 후 자식은 살아 있었다. 감사 종료 시 자식 프로세스 그룹을 정리했다.

데이터는 TemporaryDirectory만 사용하고 SSH/GitLab/Tracker에 접속하지 않았다. 재현 스크립트는 기존 테스트 준비 코드를 재사용한다.

기존 스케줄·게시·UI 회귀 테스트 21개도 재실행하여 통과했다. 이 테스트들은 위 4개 요구 보장을 검증하지 않으므로 동시에 통과할 수 있다.

## 소스만으로 확정하지 않은 항목

- `platforms/linux/bin/koda`가 Python으로 exec하고 Dockerfile은 이를 ENTRYPOINT로 사용한다. 일반 프로세스 부모 사망과 컨테이너 PID namespace 종료는 다르므로, 위 SIGKILL 재현을 컨테이너 전체의 자식 잔존 증거로 일반화하지 않는다.
- SSH의 StrictHostKeyChecking, SCP 속도 옵션, 인증/경로 오류 분류는 코드에 있다. 실제 서버의 계정 권한·호스트키·단절 시 동작은 소스만으로 확인되지 않는다.
- GitLab JSON/MR/Issue 재사용과 원본 없는 재전송은 테스트 대역으로 검증됐다. 실제 GitLab 권한·브랜치 정책·응답 유실 시나리오는 별도 통합 검증 대상이다.
- 이미지에 openssh-client 설치와 Python 코드 패키징 경로는 있다. 신규 오프라인 이미지 빌드 성공, 브라우저 표시 및 실서버 응답시간·부하 수치는 소스로 증명할 수 없다.

우선 보완할 항목은 수집 중 크기/목록 제한, 정리 실패 재시도, worker 권한 분리다. 관리자 자원 설정과 배포 형태별 종료 복구 검증도 완료 판정 전에 필요하다.

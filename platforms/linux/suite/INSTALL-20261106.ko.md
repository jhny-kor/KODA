# KODA Suite 폐쇄망 반입 및 설치 안내서

대상 파일은 `koda-suite-airgap-transfer-20261106-keyless.tar.gz`입니다. **기존 KODA Suite가 있는 서버에서는 2절의 업데이트 절차를 사용합니다.** 새 전용 서버에 처음 설치하는 경우에는 3절을 사용합니다.

## 1. 반입 파일 확인 및 압축 해제

폐쇄망 반입 절차에 따라 다음 두 파일을 서버의 같은 디렉터리로 옮깁니다. 기존 설치 경로인 `/home/user0/koda-suite` 밖의 작업 디렉터리를 사용합니다.

- `koda-suite-airgap-transfer-20261106-keyless.tar.gz`
- `koda-suite-airgap-transfer-20261106-keyless.tar.gz.sha256`

대상 서버에는 Linux x86_64, Docker Engine, Docker Compose v2, Python 3.12, Bash, OpenSSL, tar, sha256sum이 필요합니다. 기존 설치를 업데이트할 때는 설치 소유 계정인 `user0`로 실행합니다. 해당 계정에서 Docker 데몬에 접근할 수 있는지 확인합니다.

```bash
uname -m
id
python3 --version
docker info >/dev/null && docker compose version
df -h . /home/user0
```

반입 파일이 있는 디렉터리에서 아래 명령을 실행합니다. 체크섬 검사 결과가 `OK`이면 압축을 풉니다. 새 작업 폴더를 만들어 이전 반입본과 파일이 섞이는 것을 방지합니다.

```bash
archive=koda-suite-airgap-transfer-20261106-keyless.tar.gz
sha256sum -c "$archive.sha256" &&
  mkdir koda-20261106-staging &&
  tar -xzf "$archive" -C koda-20261106-staging &&
  cd koda-20261106-staging/koda-suite-airgap-transfer-20261106-keyless
```

이후 명령은 압축에서 나온 위 디렉터리에서 실행합니다. 패키지에 들어 있는 `release-public.pem`은 설치 스크립트가 릴리스 서명 검증에 자동으로 사용합니다. 이 키를 서버 설정에 따로 등록할 필요는 없습니다.

## 2. 기존 서버 업데이트

기존 운영 설정은 `/home/user0/koda-suite/tracker/.env`에서 읽습니다. 작업 시간에는 Suite 쓰기 프로세스가 잠시 정지하므로 서비스 중단 시간을 확보합니다. 백업을 위해 기존 설치 파일과 대상 볼륨의 합계에 1 GiB를 더한 디스크 여유가 필요하며, 설치 이미지와 임시 압축 해제 공간도 별도로 확보합니다.

먼저 읽기 전용 사전 검사를 실행합니다.

```bash
sh ./check.sh --prefix /home/user0/koda-suite
```

서명·무결성·기존 설정·사전 검사 완료 메시지를 확인한 뒤 업데이트합니다. `update.sh`가 PostgreSQL 덤프, 기존 설치 파일, 토큰과 대상 자료 볼륨을 비공개로 백업하고 검증한 뒤 새 릴리스를 설치합니다. `status.sh`는 업데이트 성공 후에 실행됩니다.

```bash
sh ./update.sh --prefix /home/user0/koda-suite &&
  sh ./status.sh --prefix /home/user0/koda-suite
```

명령이 서명을 검사하거나 백업하는 동안 수분간 출력이 없을 수 있습니다. 업데이트는 대상 프로세스마다 최대 120초씩 종료를 기다립니다. 명령을 중복 실행하지 말고 종료 결과를 기다립니다. 업데이트 출력의 비공개 백업 경로를 기록해 둡니다. 기본 백업 경로는 `/home/user0/koda-suite-backups/`입니다.

## 3. 새 전용 서버에 신규 설치

설치 경로는 아직 없거나 완전히 비어 있어야 합니다. 동봉된 예제를 설치 경로 밖으로 복사하고 접근 권한을 제한합니다.

```bash
install -m 0600 ./install.env.example /home/user0/koda-install.env
vi /home/user0/koda-install.env
```

| 설정 | 입력할 값 |
| --- | --- |
| `POSTGRES_PASSWORD` | PostgreSQL 관리 계정에 사용할 새 비밀번호 |
| `TRACKER_DB_PASSWORD`, `TRACKER_DATABASE_URL` | Tracker 전용 DB 비밀번호와 그 비밀번호를 포함한 연결 URL. URL에서 예약 문자를 쓴다면 비밀번호 부분을 퍼센트 인코딩합니다. |
| `TRACKER_BOOTSTRAP_ADMIN_USERNAME`, `TRACKER_BOOTSTRAP_ADMIN_PASSWORD` | Tracker 초기 관리자 계정과 비밀번호 |
| `TRACKER_LDAP_ENCRYPTION_KEY` | 서버 전용 Fernet 키. 예제 문자열을 실제 키로 바꿉니다. |
| `TRACKER_PUBLIC_ORIGIN` | 사용자가 접속할 실제 HTTPS 주소. 운영 예제는 Secure Cookie를 사용하므로 HTTPS 프록시에서 이 주소를 제공해야 로그인할 수 있습니다. |
| `PUBLIC_HTTP_BIND`, `PUBLIC_HTTP_PORT` | 내부 게이트웨이 바인딩과 포트. 기본값은 `127.0.0.1:8088`입니다. |
| `TRACKER_DATA_UPDATE_VERIFY_KEY_FILE` | 취약점 자료 검증키를 아직 등록하지 않았다면 빈 값으로 둡니다. |

Fernet 키가 필요하면 아래 명령으로 생성하고, 출력값을 설정 파일에 직접 입력합니다. `suite.env.example`은 개별 설정을 참고할 때 사용합니다.

```bash
python3 -c 'import base64, secrets; print(base64.urlsafe_b64encode(secrets.token_bytes(32)).decode())'
```

설정을 저장한 뒤 설치합니다.

```bash
sh ./install-new.sh \
  --env-file /home/user0/koda-install.env \
  --prefix /home/user0/koda-suite &&
  sh ./status.sh --prefix /home/user0/koda-suite
```

## 4. 설치 후 확인

1. `status.sh`가 성공하는지 확인합니다. Suite는 내부 게이트웨이, KODA, Tracker API 및 워커의 상태를 검사합니다.
2. 운영 HTTPS 주소의 `/`에서 Tracker에, `/koda/`에서 KODA에 접속합니다. 기존 설치는 기존 계정으로 로그인해 프로젝트와 과거 점검결과를 열어 봅니다. 신규 설치는 설정한 초기 관리자 계정을 사용합니다.
3. 앱 설치와 취약점 자료 적용은 별도입니다. 이 반입본은 앱과 도구를 포함합니다. 취약점 자료를 검증하고 적용하려면 승인된 자료 검증키를 별도로 등록해야 합니다.

사전 검사에서 오류가 나오면 오류 메시지의 항목을 확인한 뒤 `check.sh`를 다시 실행합니다. 업데이트 중 오류가 나온 경우 먼저 출력에 표시된 백업 경로와 현재 상태를 확인합니다. 백업 무결성 검사는 아래 명령으로 실행할 수 있습니다. 복구 범위는 함께 들어 있는 `restore-config.sh --help`와 `rollback.sh --help`에서 확인합니다.

```bash
sh ./verify-backup.sh --backup /home/user0/koda-suite-backups/실제백업폴더명
```

패키지의 신규 설치, 업데이트 및 데이터 보존 리허설은 격리된 Linux x86_64 컨테이너의 root 계정에서 통과했습니다. 운영 Ubuntu 서버의 UID/GID 1000 계정에서는 아직 적용 검증을 수행하지 않았습니다. 검증 범위는 동봉된 `suite-proof.json`에서 확인할 수 있습니다.
